# О проекте

Тестовое задание на позицию фуллстек-разработчика. Проект представляет собой два экрана: таблица с журналом строительных работ и таблица со справочником видов работ. Можно редактировать как список видов работ, так и сами записи. Переключение между экранами осуществляется через меню в правом верхнем углу.

## Настройка и запуск проекта

Для начала в папке server нужно создать файл .env на основе файла .env.example. Затем необходимо заполнить недостающие поля для подключения базы данных на своей стороне.

После этого необходимо в терминале запустить команду pnpm install:all.

Затем необходимо запустить серверную и клиентскую часть:

- режим разработки: в отдельных терминалах pnpm dev:server и pnpm dev:client
- готовая сборка: pnpm build, затем в отдельных терминалах pnpm start:server и pnpm start:client

Если pnpm не установлен, то можно действовать двумя следующими способами. 1. Установить pnpm на свою систему. 2. Либо в качестве альтернативы запустить 2 отдельных терминала. В одном из них перейти в папку server (cd server), в другом - в папку client (cd client). Затем действовать по инструкции выше, заменив все вызовы с pnpm на аналогичные с npm run (например, вместо pnpm install - npm run install).

## Стек

- frontend: react, typescript, react-router, redux-toolkit, rtk query, ant design, vite
- backend: express, sequelize
- architecture: FSD

## Комментарий

Мой выбор инструментов обусловлен тремя соображениями:

- популярность
- уместность для целей задачи
- насколько он знаком мне (предпочтение более знакомым)

Например, в задаче требуется делать запросы к бд с опциональными параметрами и сохранять результаты таких запросов. Один zustand для этих целей не помог бы. А продукты tanstack мне менее известны. Поэтому я выбрал redux-toolkit. Он дает возможность как хранить состояние, так и управлять запросами через свою надстройку rtk query. Это как раз то, что нужно.

В качестве библиотеки компонентов выбрал Ant Design, т.к. во-первых, он довольно популярен, а во-вторых в нем уже есть почти все компоненты. И мне практически не пришлось делать верстку.

Выбрал простую сборку на vite, т.к. next.js здесь ни к чему: здесь нет обработок картинок, нет настройки seo и т.п.

На бекенде выбрал sequelize, т.к. работал в основном с ней. Из альтернатив мне известна prisma, но она мне менее знакома.
